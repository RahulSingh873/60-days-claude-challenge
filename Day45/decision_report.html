DECISION REPORT

Cybersecurity vs. Web Development vs. AI Automation

15 July 2026

The Real Decision

You've built a year of web dev skills and projects, but your actual pull is cybersecurity — and you're also dabbling in AI automation on the side. The real trade-off: keep compounding on what you've already built, or start fresh on what you actually want, in a market where "web dev" itself feels shaky because tools like Claude can now generate front-end code fast.

The Case For Each Option

Web Development

Strongest case: You already have projects and momentum here. Least friction to an internship in the next few months.
Hidden upside: AI tools make you faster at building, not obsolete — a dev who can direct AI well ships more, not less.
Biggest weakness: It's not what you actually want to do long-term, and that gap tends to show up as burnout later.
Best if you value: speed to first internship, low risk, using what's already built.

Cybersecurity

Strongest case: It's the domain you actually want. A 1-year runway to an internship is realistic if you commit now — security hiring rewards demonstrated skill (labs, CTFs, certs) over polished resumes.
Hidden upside: Security roles are structurally harder to automate away than pure front-end work — that directly answers your job-insecurity fear.
Biggest weakness: You're starting from near-zero here. No projects, no proof yet, and 1 year is tight for a beginner to be internship-ready.
Best if you value: long-term alignment, addressing the insecurity at its root, doing what you're actually drawn to.

AI Automation

Strongest case: It's rising fast and you're already learning it — could become a strong complement to whichever core domain you pick.
Hidden upside: As a skill layered onto cybersecurity or web dev, it makes you more hireable than as a standalone specialty at your stage.
Biggest weakness: Treated as a third full domain, it splits your limited time three ways and you risk being shallow everywhere.
Best if you value: staying ahead of the curve, but only as an add-on, not your primary bet right now.

Assumption Buster

3 assumptions you may be making

  • That web dev = insecure and cybersecurity = secure. Both fields have entry-level saturation; security isn't immune to it either.
  • That switching domains now means your past year of web dev projects are wasted. They're not — they're proof you can ship, which transfers.
  • That you have to fully choose one and abandon the others right now, rather than sequencing them.

2 biases at play

Loss aversion — the fear of "wasting" your web dev work is pulling you to stay, even though your gut has already moved on.

Status quo bias — sticking with web dev feels safer simply because it's familiar, not because it's actually the better long-term bet for you.

1 thing you're definitely ignoring

You haven't named a single concrete cybersecurity skill, cert, or project you'd start with — "I want cybersecurity" is still a feeling, not a plan yet.

Premortem

If Cybersecurity fails (12 months from now)

  • You underestimated the ramp-up time and had no internship-ready proof by placement season.
  • You studied theory but never built labs, CTFs, or a portfolio — recruiters saw no evidence.
  • You kept switching focus between web dev, AI, and security and never went deep enough in any.

Early warning sign: By month 4, you still can't name one security project you've completed.

Prevention: Lock a 90-day plan — one cert path (e.g. Security+ or a TryHackMe track) plus one hands-on project, non-negotiable.

If Web Dev fails (12 months from now)

  • You landed a web dev internship but felt disengaged, since it was never the domain you wanted.
  • AI-assisted coding tools compressed junior web dev roles faster than you adapted.
  • You stopped building new projects since motivation dropped once you weren't excited by the domain.

Early warning sign: You keep deprioritizing web dev projects in favor of security content, even while "choosing" web dev.

Prevention: If you go this route, pair it with AI-automation skills immediately so you're not competing on commodity front-end work alone.

7-Day Test Plan

Day 1-2Research: map 3 realistic entry paths into cybersecurity (certs, free labs like TryHackMe/HackTheBox, relevant college electives).
Day 3-4Experiment: complete one beginner TryHackMe room or a small CTF challenge start to finish.
Day 5-6Conversation: talk to one senior/alum in cybersecurity or a security team at a target company about realistic 1-year timelines.
Day 7Decide: if the hands-on work from Day 3-4 excited you more than your web dev projects ever did, commit to cybersecurity as primary.

The Verdict

Cybersecurity — as primary, web dev as your bridge

It wins because it's the only option that resolves your job-insecurity fear at the root instead of just avoiding it, and it scores highest on the dimensions that matter for a 1-year, beginner-to-internship goal: alignment, growth, and regret risk.

What could flip it: If the 7-day test shows you don't actually enjoy the hands-on security work as much as you assumed — that's real signal to fall back to web dev + AI automation instead.

Hard truth: wanting cybersecurity and being ready for a cybersecurity internship are two different things — the next 90 days of actual work decide which one is true for you.
